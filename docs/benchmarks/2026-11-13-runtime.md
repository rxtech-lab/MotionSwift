# Retained runtime microbenchmark — 2026-11-13

Measured on macOS arm64 with the debug Swift build. The 100 samples repeatedly
seek frames 0–19 in the lifecycle fixture (effects, delayed timers, promises,
module-local state and conditional host children). Compilation is outside both
timers. Retained evaluation includes the first native-tree commit.

| Worker policy | Total time | Time per sample |
|---|---:|---:|
| One retained worker | 23.30 ms | 0.233 ms |
| Create a worker for every sample | 512.24 ms | 5.122 ms |

The retained worker was **21.98× faster** in this local measurement and emitted
853 mutations. Repeated identical frames emit zero mutations (verified separately).
The fresh-worker reference uses the **same current runtime**, including its module
reset and mutation transport. It is not an exact historical measurement of the old
JSON-snapshot implementation. This isolates worker reuse; it does not establish
video speedup, allocation/RSS savings, GPU throughput or performance on iOS.

Reproduce with `make runtime-benchmark` (or `node tests/perf/runtime.mjs` after
bootstrap). Pass Swift options through the script, for example
`node tests/perf/runtime.mjs -c release`. It writes machine-readable results,
a Markdown summary and the complete test log under `bench-results/runtime/`.
Results vary with build configuration, workload and machine load; this is an
informational benchmark, without a CI timing threshold.

The acceptance tests compare fresh-worker, sequential and shuffled retained trees,
compare sequential/shuffled PNG output, exercise props/source/composition and
explicit cache invalidation, and require actionable timeout, cancellation,
rejection, thrown callback and duplicate-handle errors. See
`tests/Swift/RetainedRuntimeTests.swift` and `RetainedRuntimePixelTests.swift`.
