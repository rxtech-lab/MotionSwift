# Sampled benchmark memory (2026-11-12)

Machine: Apple M4 Max, 16 cores, 128 GB, macOS kernel darwin 27.2.0 (arm64). Eight workers per engine; one measured run per cell, no warmup. Release binary rebuilt from the current working tree before measurement. These are synthetic fixtures; the full Test Film was not measured in this snapshot.

Process-tree RSS is sampled approximately every 100 ms, including compiler, Chrome and FFmpeg descendants. MiB = 1,048,576 bytes. Peaks may be missed, shared pages may be counted more than once, and GPU/media-engine allocations are not separately measured. These figures are not total physical memory pressure or a leak test. Sampling overhead is included in wall times.

All 108 render cells passed frame-count/metadata checks and all applicable SSIM checks (>= 0.98). Remotion runs at 180p/720p only, as configured.

## Reproduce

```sh
node tests/perf/bench.mjs --runs 1 --warmup 0 --allow-unavailable-hardware --out tests/reports/bench/memory-short
node tests/perf/bench.mjs --config tests/perf/bench.long.config.json --runs 1 --warmup 0 --allow-unavailable-hardware --out tests/reports/bench/memory-long
```

Raw reports and sample counts are in the corresponding `results.json`; logs and summaries are adjacent. These report directories are gitignored.

## Example app full-film render path

The example's export model was also exercised directly in a Release hardware integration test: all 2,700 frames of the benchmark Test Film produced a 1920×1080, 90-second H.264 movie through Metal → IOSurface → VideoToolbox with eight workers. The test took 23.2 seconds and observed approximately 9.2 GiB peak resident memory in the test host. This includes the test host, compiled film and preview state; it is a separate measurement from the process-tree matrix above and is not a GUI-process measurement. It shows that full-length rendering still has substantial memory use, even with shared surfaces.

```sh
MOTIONSWIFT_TEST_HARDWARE=1 swift test -c release --no-parallel --filter showcaseExportsFullBenchmarkFilmWithMemory
```

The example displays live RSS and a preview peak on the Test Film destination. Its export sheet resets the render peak on each run, displays progress in an overlay, supports Stop, and freezes the completed render's peak. Visual verification of the app window was blocked because Computer Use was not approved to access the showcase app.
