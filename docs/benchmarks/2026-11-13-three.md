# 3D scenes: Remotion three.js vs native Metal (2026-11-13)

`node tests/perf/three.mjs` on an Apple M4 Max (16 cores, 128 GB), eight workers per engine, one run after one warmup. Pins: Remotion 4.0.542, `@remotion/three` 4.0.542, three.js 0.187.0, `@react-three/fiber` 8.18.0, Chrome for Testing 157.0.8103.39 with `gl: 'angle'`. Each fixture is 90 frames at 30 fps. 360p is 640×360 (scale 1). 1080p is 1920×1080 (scale 3); in both engines R3F renders the WebGL-equivalent canvas at dpr 2 and the result is upscaled. Times are wall clock and include startup, compilation or bundling, rendering and H.264 encoding (x264 CRF 18 for Remotion, CPU and GPU; VideoToolbox for `gpu-shared`). SSIM compares each native video with Remotion's.

| Fixture | Tier | Remotion | CPU + x264 | Metal + x264 | Metal + shared IOSurface/VideoToolbox |
|---|---|---:|---:|---:|---:|
| CrystalOrbit | 360p | 12.96 s | 1.28 s (10.13×, SSIM 0.9787) | 1.29 s (10.00×, 0.9787) | 1.26 s (10.32×, 0.9743) |
| NeonCity | 360p | 12.86 s | 1.71 s (7.50×, 0.9842) | 1.64 s (7.84×, 0.9842) | 1.61 s (8.01×, 0.9793) |
| ProbeFleet | 360p | 12.98 s | 1.19 s (10.93×, 0.9794) | 1.23 s (10.59×, 0.9794) | 1.18 s (10.97×, 0.9768) |
| CrystalOrbit | 1080p | 24.83 s | 1.82 s (13.64×, 0.9844) | 1.77 s (14.06×, 0.9844) | 1.66 s (14.97×, 0.9831) |
| NeonCity | 1080p | 25.08 s | 2.19 s (11.44×, 0.9891) | 2.08 s (12.05×, 0.9891) | 1.63 s (15.38×, 0.9877) |
| ProbeFleet | 1080p | 25.17 s | 1.45 s (17.36×, 0.9810) | 1.52 s (16.51×, 0.9810) | 1.51 s (16.70×, 0.9803) |

Geometric-mean speedup over Remotion: **11.45×** (CPU + x264), **11.51×** (Metal + x264), **12.32×** (Metal + shared IOSurface/VideoToolbox). All cases passed the parity gate (SSIM ≥ 0.97, identical frame counts and dimensions).

3D work runs on Metal for every backend. The Skia backend only composites the canvas, so CPU and Metal timings are close. Video SSIM includes lossy encoding by both engines. Still-frame parity is measured separately by `make three-visual`: on 17 frames, 0.2–2.9% of pixels changed and 0–0.15% differed by more than 8 levels, at 52–79 dB PSNR.

## Single-worker frame cost

`motionswift budget --compiler=tsgo --frames=0-9` (one worker, 640×360):

| Fixture | JS (React + scene description) | Paint (3D + composite) | Total p50 |
|---|---:|---:|---:|
| NeonCity (1,200+ meshes) | 33.0 ms | 7.7 ms | 40.8 ms |
| CrystalOrbit (~220 meshes) | 7.0 ms | 5.2 ms | 12.3 ms |

For large scenes, JavaScript evaluation (React reconciliation and JSON scene serialization) dominates, not GPU rendering. Workers scale almost linearly: NeonCity takes 3.5 s with one worker and 0.75 s with eight.

## Reproduce

```sh
make bootstrap build
make three-goldens          # only when references must change; review the PNGs
make three-visual           # still-frame parity, CPU and GPU compositing
node tests/perf/three.mjs   # this table; --report-only skips the speed gate
```
