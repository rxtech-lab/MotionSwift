Wall times include compilation/startup, real availability probe, render, encode and publish. Every cell passed decoded frame count, codec and dimension checks. The delivered [H.264 snapshot](2026-11-12-hardware-encoding.md) remains the historical baseline. These runs refresh H.264 alongside every new codec using the same current CLI and process-tree RSS instrumentation. Historical timings are not directly interchangeable: the current compiler/build and the additional pre-render availability probe differ, and the old snapshot did not measure this exact matrix. A lower time ratio above is faster; quality settings differ across codecs.

Budgets in `tests/perf/codec-budgets.json` allow 50% above each measured median wall time and sampled peak RSS. This is an initial regression guard for this host class and this fixture, not a universal codec performance promise. The existing general Remotion benchmark is unchanged. No 4K or device/iOS codec budgets were established here.
