# Implementation plan

> Current executable behavior and remaining work: [runnable implementation](current-implementation.md). This document describes the target architecture and roadmap.

Durations assume 1–2 engineers. Each phase ends with **exit criteria checked by the CI output-check suite** ([tests/README.md](../tests/README.md)), not by manual review. The test harness is built in Phase 0, before engine features, so every feature arrives with goldens.

```text
Phase 0  Validation spike + test harness         wk 1–2    ── go / no-go gate
Phase 1  Skia + swc compiler packaging, SkiaKit   wk 3–4
Phase 2  Runtime, reconciler, layout, core boxes wk 5–8
Phase 3  Paint coverage (effects, text, SVG)     wk 9–13
Phase 4  Media: images, video, audio, fonts      wk 14–17
Phase 5  Output pipeline + CLI + concurrency     wk 18–20  ── internal beta (macOS render)
Phase 6  SwiftUI editor                          wk 21–26
Phase 7  Linux render worker                     wk 26–29  ── Remotion Lambda replacement
Phase 8  Hardening, fallbacks, Tailwind          wk 30+
```

---

## Phase 0: Validation spike and test harness (weeks 1–2)

**Goal:** prove, on real content, that the speedup and visual parity are achievable before investing further.

Tasks:

1. Collect 5–10 real compositions generated by Film Studio and copy them into `tests/compositions/real/`.
2. Profile them in Remotion with `--log=verbose` and record the per-stage breakdown in `tests/perf/baseline/`.
3. Build the golden generator: a pinned Remotion project that renders the fixture frames as PNG stills ([tests/README.md → Golden generation](../tests/README.md#golden-generation)).
4. Spike engine (throwaway quality, macOS only):
   - Use a prebuilt Skia (for example from the `skia-binaries` or `rust-skia` artifacts) through a minimal C shim.
   - JSC host with a minimal `remotion` shim (`useCurrentFrame`, `useVideoConfig`, `interpolate`, `spring`, `AbsoluteFill`).
   - Minimal reconciler, Yoga layout, and painting for `div` backgrounds, border-radius, text (SkParagraph), images, 2D transforms, and opacity.
   - AVAssetWriter output, without a zero-copy path yet.
5. Write the pixel-diff comparer (`compare` tool) and run it on the spike output against the goldens.
6. Build the benchmark script and the `benchmark.yml` workflow ([benchmark.md](benchmark.md)), so every PR from now on gets a Remotion-vs-native comment. Until the engine exists, the comment records only the Remotion baseline.

**Exit criteria (go/no-go):** evaluated on 2026-11-12 in [phase0-validation.md](phase0-validation.md). Result: **no-go**. 0 of 15 real Film Studio compositions are in the supported subset.

- [ ] ≥ 5× faster wall time than Remotion on the real fixtures for the supported subset, excluding startup, as reported by the benchmark comment. *Not measurable: empty supported subset. Remotion baselines are recorded.*
- [ ] Non-text regions pass the default pixel thresholds. *Not measurable: no real fixture renders natively.*
- [ ] Text regions are within the text threshold, or the failures are understood and have a fix plan (for example SkParagraph line-height or font-hinting settings). *Failed: text paint is not implemented. The fix plan is [remaining blockers](phase0-validation.md#remaining-blockers).*
- [x] A written decision on C shim versus Swift C++ interop for `CSkia`. *[C ABI shim](phase0-validation.md#cskia-decision-c-abi-shim).*

If text parity fails badly, make SkParagraph tuning the next phase before anything else.

## Phase 1: Skia and compiler packaging, SkiaKit (weeks 3–4)

- `compiler/` Rust crate on `swc_core`: TS strip, JSX automatic runtime, ESM → module-registry form, source maps, and the source-stamp transform. Expose it through a C ABI and prebuild it with `CSkia` in the same workflow.
- `MotionCompiler` Swift side: the resolver (Node algorithm, `exports` conditions, tsconfig `paths`, aliases, allowlist), the module graph, and the content-hash transform cache.

- Choose and pin the Skia milestone, matching the Chrome Headless Shell version Remotion pins where possible.
- CI workflow `skia-build`: run `gn`/`ninja` for macOS (arm64, x86_64), iOS (device and simulator), and Linux (x86_64, arm64), and produce `CSkia.xcframework` and `libcskia.so` with checksums.
- `CSkia` C ABI covering canvas, paint, path, shaders (gradients), image filters, color filters, blend modes, SkParagraph, SkSVG, and Graphite-Metal/Vulkan contexts.
- `SkiaKit` Swift wrappers with ownership-safe handles.
- Unit tests: draw primitives and compare with goldens generated by Skia itself (renderer self-consistency, not Remotion parity).

**Exit:** `swift build` works on a clean macOS and Linux machine using only the prebuilt artifacts. The SkiaKit self-tests and the compiler snapshot tests (`tests/compiler-fixtures/`) are green, and every `tests/compositions/` project compiles through `MotionCompiler`.

## Phase 2: Runtime, reconciler, layout, and core boxes (weeks 5–8)

- `MotionRuntime`: JSContext per worker, loading the module graph produced by `MotionCompiler`, the op-buffer bridge, the deterministic `Math.random` and `Date`, and `delayRender` bookkeeping.
- `js/remotion-shim` (`@motionswift/remotion`): everything marked phase 0–2 in [compatibility.md](compatibility.md), plus the subset `.d.ts` and type tests against upstream Remotion types.
- JS runtime globals (`console`, timers, `fetch`, `URL`, `TextEncoder`, ...) as listed in [typescript-and-packages.md](typescript-and-packages.md#js-runtime-environment).
- `@motionswift/tsconfig` and `@motionswift/cli` (`check`, `still`).
- `js/reconciler`: host config, style diffing, op serialization.
- `MotionLayout`: style parsing, Yoga sync, text measurement through SkParagraph, and transforms.
- `MotionRender`: backgrounds, borders, radii, overflow clipping, opacity layers, and `z-index` ordering.
- `motionswift still` CLI.
- Motion-parity test layer running (layer 1).
- Layout-parity test layer running (layer 2).

**Exit:** layers 1–3 green for `tests/compositions/core/*`, and the frame-order independence test green.

## Phase 3: Paint coverage (weeks 9–13)

- Gradients (linear, radial, conic), `box-shadow`, `filter`, `backdrop-filter`, `mix-blend-mode`, `clip-path`, `mask-image`, and 3D transforms.
- Full text features: inheritance, `text-shadow`, stroke, ellipsis, line clamp, `background-clip: text`, and Chrome's user-agent defaults for headings and paragraphs.
- Inline SVG mapping, plus SkSVG for external SVGs.
- `@remotion/paths`, `@remotion/shapes`, `@remotion/transitions`.
- `js/lint` (`@motionswift/eslint-plugin`) with all rules and lint fixtures. `motionswift check` combines tsc, lint, and resolve checks and emits JSON diagnostics.

**Exit:** layer 3 green for `tests/compositions/effects/*`, `text/*`, and `svg/*`, and every lint rule covered by a failing fixture.

## Phase 4: Media (weeks 14–17)

- Image decode cache (PNG/JPEG/WebP/AVIF/GIF first frame), with `object-fit`/`object-position`.
- `OffthreadVideo`/`Video`: VideoToolbox decode that is frame-accurate, timestamp math identical to Remotion (`startFrom`, `playbackRate`), and an IOSurface texture for each frame.
- `Audio`: decode, per-frame volume curves from JS, mixing, and AAC encode.
- Fonts: `loadFont`, `@remotion/google-fonts` (cached download), and system fallbacks matching Chrome's on each platform.

**Exit:** layer 3 green for `tests/compositions/media/*`. Layer 4 checks audio duration, sample rate, and loudness within ±0.5 LUFS of the Remotion render.

## Phase 5: Output pipeline, CLI, and concurrency (weeks 18–20)

- Zero-copy Graphite-Metal → IOSurface → `VTCompressionSession`, with H.264, HEVC, ProRes, and an alpha channel for ProRes 4444.
- Map Remotion render flags (`--codec`, `--crf`, `--pixel-format`, `--every-nth-frame`, `--frames`, `--scale`, `--props`).
- Worker pool, reorder buffer, and optional segment concat.
- `motionswift render`, which follows the CLI contract in [benchmark.md](benchmark.md#native-cli-contract), including `--report-json` stage timings.

**Exit:** layer 4 (video output checks) green, the performance budgets in [performance.md](performance.md) met on the reference machine, and the PR benchmark switched to `--fail-on-regression`. **Internal beta: Film Studio on macOS can render through MotionSwift behind a feature flag, falling back to Remotion when lint fails.**

## Phase 6: SwiftUI editor (weeks 21–26)

See [editor.md](editor.md).

- `MotionStudio` pure SwiftUI app shell: `NavigationSplitView`, preview canvas, transport bar, timeline, inspector, a dedicated sheet for each create/update/delete action, overlays for status, and native confirmations.
- Selection: source stamps, the source index, hit testing, and property classification (static / animated / bound / computed).
- Canvas: drag, resize, and rotate handles drawn in a SwiftUI overlay, snapping, preview overrides, and gesture → edit-operation mapping for absolutely positioned and flex elements, plus transform-list editing.
- Timeline: sequence bars (move, change duration, trim, reorder `Series`), the Composition Settings sheet, and keyframe lanes for `interpolate`, `spring`, and `interpolateColors`, with the easing and spring sheets. Curves are evaluated by the engine.
- The AST edit service (ts-morph) with inverse operations, wired to `UndoManager`.
- Hot reload that keeps the selection, and the scrubbing preview worker.
- iOS/iPadOS build (JSC without JIT; measure the JS budget) with haptics and touch gestures. The iOS vendor bundle (React, the shim, and allowlisted packages) is precompiled in CI. Projects that need packages outside it sync their module graph from a Mac or the cloud.

**Exit:** editor tests green:

- `tests/editor-fixtures/` byte-exact, including inverse operations.
- Gesture-mapping unit tests.
- Round-trip pixel tests, where the preview override frame must equal the committed frame.
- XCUITests for select, drag, resize, rotate, timeline drag, and keyframe edits.

## Phase 7: Linux render worker (weeks 26–29)

- Linux builds of every module, with JSC via a pinned `libjavascriptcoregtk`.
- Graphite-Vulkan, with Skia CPU raster as the fallback.
- ffmpeg encode/decode with hardware acceleration where available.
- An OCI image (`motionswift-worker`), job API (input: bundle URL, composition, props; output: a presigned S3 upload of the result), and chunked rendering across machines with segment concat.

**Exit:** the full CI suite green on Linux (CPU raster). Linux output matches macOS output within the cross-platform thresholds. Cloud cost per rendered minute is lower than Remotion Lambda for the reference fixtures.

## Phase 8: Hardening and extensions (week 30+)

- WebKit fallback for marked subtrees on macOS: render to an offscreen `WKWebView`, snapshot, and composite.
- A compile-time transform from Tailwind `className` to inline styles.
- Skottie for `@remotion/lottie`.
- Fuzzing: random style generation compared with Chrome, to find parity gaps automatically.

## Risk register

| Risk | Impact | Mitigation |
|---|---|---|
| Text layout differs from Chrome LayoutNG (line breaks, baseline, hinting) | High: the most visible difference | Phase 0 gate. Match Chrome's font settings (subpixel positioning, no hinting on macOS, `font-smoothing`). Use separate text thresholds. Measure per-line boxes in the layout-parity layer. |
| Skia build complexity | Medium: slows everyone down | Prebuilt artifacts. One person owns `CSkia`. Pin the version. |
| Agent output uses CSS outside the subset | Medium: renders fail | Lint inside the generation loop, Remotion fallback in Film Studio, and track the rejection rate to prioritize new features. |
| Third-party npm packages assume a DOM or Node built-ins | Medium | Resolve-time allowlist, `ms/unsupported-package` lint, and a vendor bundle of known-good packages. |
| swc version drift or Rust toolchain burden | Low | Pin `swc_core`, prebuild artifacts, and use snapshot tests for compiler output. |
| JSC on Linux (packaging and version drift) | Medium | Pin a version and vendor the build in the worker image. Motion parity tests run on Linux in CI. |
| `Math.*` ulp differences between JSC and V8 | Low | Tolerance-based motion parity test. Differences are sub-pixel. |
| Remotion behavior changes in new versions | Medium | Pin the Remotion version in the golden generator. Upgrading Remotion means a PR that regenerates goldens and reviews the diffs. |
| Remotion licensing for reused code | Medium | Clean-room shim, with a legal review before reusing any Remotion source. |
| Benchmark noise on GitHub-hosted runners | Low | Use the `BENCH_RUNNER` self-hosted runner, warm-up runs, median of several runs, and show the machine in the comment. Treat results as informational until Phase 5. |
| Canvas gestures on computed or complex expressions | Medium | Property classification. Refuse gestures with an explanation rather than produce surprising source rewrites. |
| iOS without JIT is too slow for complex compositions | Low (preview only) | Reduce preview resolution and frame rate, or render remotely. |

## Definition of done for any engine PR

1. Every new CSS property or API has at least one fixture in `tests/compositions/` with goldens.
2. [compatibility.md](compatibility.md) is updated (status column), and the shim's `.d.ts` exposes the new API or CSS property.
3. The CI output-check suite is green on macOS and, from Phase 7, on Linux.
4. Perf job is within budget, or the regression is explained in the PR.
