## CSkia decision: C ABI shim

**Decision:** keep a narrow C ABI (`msk_*` in `Sources/CSkia/skia.h`) as the only boundary between Swift and Skia. Do not adopt Swift C++ interop for `CSkia`. Today the shim is implemented in Rust over rust-skia 0.99 (`native/src/lib.rs`). That choice is kept for Phase 1. A C++ shim compiled directly against a self-built Skia remains the fallback if the rust-skia release cadence prevents pinning the Skia milestone Remotion's Chrome uses.

Reasons:

1. **Contained build impact.** C++ interop has to be enabled in every Swift module that imports `CSkia`, and in their clients: SkiaKit, MotionRender, the CLI, the future SwiftUI editor, and Film Studio. Every one of those targets would then compile Skia's C++ headers, and Linux builds would depend on matching libc++ headers. A C header keeps all of that inside one prebuilt artifact, which suits the Phase 1 XCFramework/`.so` plan and the Phase 7 Linux worker.
2. **Skia's API is a poor fit for interop.** It relies on `sk_sp<T>` intrusive ref-counting, templates, builder objects and `SkSL` strings. Swift C++ interop supports these types only partially, and in practice they would need hand-written C++ wrappers anyway, which is a shim under another name.
3. **Per-call overhead does not matter at this boundary.** The architecture batches work per frame (op buffers, one surface per worker), so crossing a C boundary costs little next to rasterization. This was not separately micro-benchmarked. It follows from the call granularity.
4. **Already validated.** The existing shim carries the precision-sensitive GPU work: fractional-coverage SkSL quads, color-matrix layer opacity, F16 targets, and IOSurface handoff. These pass the exact-RGBA golden gate on both backends.

Costs accepted: every new Skia feature (SkParagraph, SkSVG, shaders, image filters) needs C entry points and Swift wrappers, and a Rust toolchain stays in the build. The Rust toolchain is already required for the planned swc compiler crate.

## Remaining blockers

The gate cannot be re-evaluated until enough of the following lands for at least 5 real fixtures to render:

1. **Text:** SkParagraph measurement in Yoga, paint, and `textAlign`/`fontWeight`/`lineHeight`/`letterSpacing`/`whiteSpace`, plus heading/paragraph/`br` defaults. Affects 15/15 fixtures. This is the first priority under the plan's text-failure rule.
2. **Inline SVG** element mapping (shapes, paths, groups, gradients, clip paths, SVG text). Affects 11/15.
3. **Core CSS completion:** `border*` shorthands, `transformOrigin`, `flex` shorthand, inline display modes, `zIndex`, and `position: fixed`, plus accepting `pointerEvents`.
4. **Effects:** CSS gradients, `boxShadow`, `filter`, `mixBlendMode`.
5. **Shim:** `Easing.bezier`/`ease`/`back` and `random()`. Unknown APIs must produce a diagnostic, not a runtime `TypeError` (fs06).
6. **Shareable fixtures:** anonymize at least 5 projects so that the real-fixture goldens and benchmark can run in CI instead of only on one machine.

When text and SVG are in, rerun `check`. For every fixture that passes, generate goldens, run the pixel gate, and add it to the benchmark against the baselines above.
