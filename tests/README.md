# Output-check test suite

This folder holds the CI suite that proves MotionSwift's output matches Remotion's. Nothing here depends on engine internals. Every check runs the `motionswift` CLI as a black box and compares its output with **goldens produced by real Remotion**.

> The Phase 0 suite now runs: `make test visual benchmark`. See [the implemented contract](../docs/current-implementation.md) for the exact active gate and remaining layers. Visual sources are in `compositions/visuals/`, test dependencies in this folder, and the same fixtures feed the benchmark. The extended layers below are the design specification.

**Active CI:** every push and same-repository PR on `[self-hosted, macOS, ARM64]`, exact RGBA comparison with a maximum 0.3% changed pixels, plus native repeatability. References are committed Remotion PNGs; ordinary CI never regenerates them.

## Fixture manifest (`fixtures.json`)

Each fixture declares what to check. Thresholds are per fixture so that known gaps are visible instead of loosened globally.

```jsonc
{
  "remotionVersion": "pinned in compositions/package.json",
  "fixtures": [
    {
      "id": "core/flex-row-gap",
      "composition": "FlexRowGap",
      "props": {},
      "frames": [0, 15, 29],          // or "all" or {"every": 5}
      "checks": ["motion", "layout", "pixel"],
      "thresholds": "default",
      "platforms": ["macos", "linux"]
    },
    {
      "id": "text/wrap-long-title",
      "composition": "WrapLongTitle",
      "frames": [0, 45],
      "checks": ["layout", "pixel"],
      "thresholds": "text",
      "knownIssue": null                // or a link to an issue; a known issue still runs and reports, but doesn't fail
    },
    {
      "id": "media/offthread-video-rate",
      "composition": "VideoPlaybackRate",
      "frames": {"every": 10},
      "checks": ["pixel", "video"],
      "thresholds": "media"
    }
  ]
}
```

## Golden generation

Goldens are generated by **Remotion itself**, never by MotionSwift.

- `tools/generate-goldens` runs in the pinned `compositions/` project:
  - **stills:** `npx remotion still src/index.ts <Comp> golden/stills/<comp>/<frame>.png --frame=<n> --image-format=png --scale=1`
  - **layout:** a Puppeteer script using Remotion's bundle and `selectComposition`. It sets the frame and dumps `getBoundingClientRect()`, the computed transform, and per-line text boxes (via `Range.getClientRects()`) for every element with `data-ms-src`.
  - **motion:** Node script that imports the compositions' motion helpers and records `interpolate`/`spring` outputs for every frame in a JSON trace.
  - **video:** `npx remotion render` followed by `ffprobe` metadata, sampled-frame hashes, and EBU R128 loudness.
- Goldens are committed through **Git LFS** (`tests/golden/** filter=lfs`).
- Goldens are regenerated **only** by the manual `regenerate-goldens` workflow. It opens a PR with before/after images, so every golden change gets reviewed. Upgrading Remotion or Chrome Headless Shell always goes through this workflow.
- Generation runs on Linux (`ubuntu-latest`) with fonts installed from `compositions/fonts/` only, so system fonts don't make goldens differ between machines.

## Check layers

Layers run in order. Each layer narrows down where a failure comes from: a layout failure tells you not to bother debugging pixels.

### Layer 1: Motion parity

- MotionSwift runs the same helpers in JSC (`motionswift trace <comp>`) and writes a JSON trace.
- Assertion: for every sampled value, `|Δ| ≤ 1e-9`. Exact equality is not required because of the `Math.*` ulp differences explained in [compatibility.md](../docs/compatibility.md#motion-determinism).
- Also asserts that `Sequence`, `Series`, and `Loop` frame remapping produce the same local frame numbers.

### Layer 2: Layout parity

- `motionswift still --dump-layout` writes boxes for every `data-ms-src` node.
- Assertions: box `x/y/w/h` within **±0.5 px** (non-text) or **±1 px** (text boxes), the same number of text lines, and per-line widths within ±2 px.
- The report lists the first mismatched node with its source location.

### Layer 3: Pixel parity (stills)

`tools/compare` produces several metrics, and a fixture must pass all of them under its threshold profile:

| Metric | `default` | `text` | `media` | `cross-platform` |
|---|---|---|---|---|
| Per-pixel tolerance (YIQ delta, pixelmatch-style) | 0.1 | 0.15 | 0.1 | 0.1 |
| Max % of pixels over tolerance | 0.3 % | 0.3 % | 0.3 % | 0.3 % |
| SSIM (luma) | ≥ 0.995 | ≥ 0.985 | ≥ 0.98 | ≥ 0.995 |
| FLIP mean error | ≤ 0.01 | ≤ 0.02 | ≤ 0.03 | ≤ 0.01 |
| Anti-aliasing pixels ignored | yes | yes | yes | yes |

- Text regions (from the layout dump) can be scored with the `text` profile while the rest of the frame uses `default`.
- Outputs for each failure: `reports/<id>/<frame>/{expected,actual,diff,heatmap}.png`.
- `cross-platform` compares MotionSwift's macOS output with its Linux output. It is not compared with Remotion.

### Layer 4: Video output checks

Runs `motionswift render` for fixtures that include `"video"` in `checks`:

- `ffprobe`: codec, pixel format, resolution, fps, frame count (exact), duration (±1 frame), and audio sample rate and channels.
- Sampled frames decoded from the MP4 are compared with the golden stills using a looser `media` profile, because both sides went through lossy encoding.
- Audio: loudness within ±0.5 LUFS, duration within ±1 audio frame, and cross-correlation peak at a 0 ms offset (±1 ms) to catch A/V sync drift.

### Layer 5: Performance tracking

Specified in [docs/benchmark.md](../docs/benchmark.md).

- `tests/perf/bench.mjs` renders the `bench.config.json` fixtures with both Remotion and `motionswift`, checks SSIM parity between the two outputs, and compares the native time with the latest `main` run.
- Runs on **every pull request** (`benchmark.yml`) and **posts or updates one sticky PR comment** with the comparison table. Results are uploaded as the `bench-results` artifact, and `main` runs serve as the baseline for PRs.
- Runner: the `vars.BENCH_RUNNER` repository variable (a self-hosted Apple Silicon runner is recommended), falling back to `macos-15`.
- Informational until Phase 5. After that, a native slowdown of more than 15% fails the check.

### Determinism checks (run with layer 3)

- **Frame-order independence:** render the fixture frames in shuffled order with a single worker, then in order with N workers. The output must be **bit-identical** between the two MotionSwift runs.
- **Repeatability:** run the same fixture twice on the same machine and backend. The output must be bit-identical.

### Compiler and type fixtures

- `compiler-fixtures/<case>/`: `input.tsx` goes through `MotionCompiler` and is compared with a snapshot of `output.js` and the source map, both with and without source stamping. Covers enums, namespaces, `satisfies`, `paths` aliases, CJS interop, asset imports, and `exports` conditions.
- Resolver cases: the expected module graph for small `node_modules` trees, including the error for a disallowed package (DOM or Node built-ins).
- **Cross-host determinism:** the same project compiled on macOS and Linux must produce byte-identical output.
- `type-fixtures/<case>.tsx`: running `tsc --noEmit` with `@motionswift/tsconfig` must fail with the expected diagnostic (for example `display: 'grid'`, `import { IFrame } from 'remotion'`). `type-fixtures/valid/` must pass.
- Every project in `compositions/` must pass `motionswift check` with zero diagnostics.

### Lint and editor fixtures

- `lint-fixtures/<rule-id>/*.tsx` must fail lint with exactly that rule ID, and `lint-fixtures/valid/*.tsx` must pass.
- `editor-fixtures/<case>/`: apply `op.json` to `before.tsx` and compare the result with `after.tsx` byte for byte. Applying the inverse operation must restore `before.tsx` exactly. The edited file is then rendered and must pass layer 3 against its own golden. Cases cover style, transform functions, text, keyframes, springs, sequence timing, composition settings, and inserting and removing elements ([docs/editor.md](../docs/editor.md#editor-tests)).

## Extended CI workflows (roadmap)

| Workflow | Trigger | Runner | Runs |
|---|---|---|---|
| `output-check.yml` | PR, push to `main` | `macos-15` (CPU raster backend), `ubuntu-latest` (CPU raster) | compiler + type fixtures → lint fixtures → `check` on all compositions → layer 1 → layer 2 → layer 3 → layer 4 (`--backend=cpu`) |
| `output-check-gpu.yml` | push to `main`, nightly | self-hosted Apple Silicon | layers 3–4 on Graphite-Metal |
| `benchmark.yml` | every PR, push to `main` | `vars.BENCH_RUNNER` or `macos-15` | layer 5: Remotion vs native → sticky PR comment + `bench-results` artifact ([spec](../docs/benchmark.md)) |
| `regenerate-goldens.yml` | manual (`workflow_dispatch`) | `ubuntu-latest` | Remotion goldens → PR with visual diff |
| `skia-build.yml` | changes to `third_party/skia.lock` | macOS + Linux | builds and publishes `CSkia` artifacts |

Notes:

- CPU raster runs on every PR because it is deterministic and available everywhere. GPU raster can differ slightly in anti-aliasing, so the GPU job uses the same thresholds and also tracks the CPU-vs-GPU diff as a metric.
- Every job uploads `tests/reports/` as an artifact, including a static HTML report with side-by-side images, a slider, and heatmaps. The report link is posted in the PR summary.
- Fixtures with `knownIssue` set are reported but don't fail the job. A fixture that starts passing while marked `knownIssue` fails the job, so the marker gets removed.

## Adding a fixture

1. Add the composition under the right folder in `compositions/` and register it in `src/Root.tsx`.
2. Add an entry to `fixtures.json`.
3. Run the `regenerate-goldens` workflow, or run `tools/generate-goldens --only <id>` locally with the pinned toolchain, and commit the goldens through LFS.
4. Update the status of the feature in [docs/compatibility.md](../docs/compatibility.md).
